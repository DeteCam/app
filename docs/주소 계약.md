# 앱 ↔ 수신기 주소(API) 계약 (초안)

- 상태: 초안 (2026-11-26). 수신기 펌웨어가 없으므로 구현하며 고친다. 바꾸면 이 문서와 receiver를 같은 변경에서 고친다.
- 연결: 측정 중에는 수신기 호스트(CM4)의 내장 BLE로 잇는다. 요청 · 응답 · 알림을 BLE 특성으로 주고받고, 내용은 아래 표의 이름과 JSON을 그대로 쓴다. 구체 식별자와 긴 내용을 나눠 보내는 방법은 구현하며 정한다.
- BLE가 CSI 측정을 방해하면 Pico W 무선(HTTP + WebSocket, 아래와 같은 이름)으로 바꾼다. 어느 쪽을 쓸지는 벤치에서 정한다([docs 현재_방향.md](https://github.com/DeteCam/docs/blob/main/현재_방향.md) U7).
- 수신기의 내장 Wi-Fi는 CSI 드라이버와 충돌할 가능성이 높아 측정 중 연결에 쓰지 않는다.
- 우도 지도 원본은 보내지 않는다. 수신기가 계산한 결과(위치, 방향, 구역, 안내)만 보낸다. 버전은 이름의 `v1`.

| 이름 | 방법 | 설명 | 주요 내용 |
|---|---|---|---|
| `/api/v1/status` | GET | 수신기 상태 | 배터리, AX210 · 스위치 · 끄덕이기 상태, 보정표 버전 |
| `/api/v1/room` | PUT | 방 지도 전달 | 공간 종류(시험실 / 시험실 밖), 방 크기(가로 · 세로 · 높이), 벽 · 천장 · 바닥 면. 시험실이면 폰이 자동으로 찾은 책상 후보. 좌석 배치도 · 응시자 자리는 받지 않는다 |
| `/api/v1/devices` | GET | 주변 기기 목록과 카메라 판별 결과 | 기기별 임시 번호(MAC은 화면에 일부만), 채널, 카메라 확률, 근거, CSI를 얻을 수 있는지 |
| `/api/v1/stimulus` | POST | 자극 구간 표시(시험실 밖에서만) | 시작 · 끝 시각, 종류(조명 · 움직임) |
| `/api/v1/spots` | POST | 측정 자리 등록 | 자리 번호, 수신기 위치 · 방향(폰 AR 좌표), 놓인 면(유전체 / 금속) |
| `/api/v1/measure` | POST | 한 자리 측정 시작 | 자리 번호, 대상 기기 → 측정 번호. 수신기가 세 자세로 끄덕이며 잰다 |
| `/api/v1/measure/{id}` | GET | 한 자리 결과 | 지도 퍼짐, 믿을 만한 정도(믿을 만함 / 믿기 어려움), 실패 여부와 이유 |
| `/api/v1/calibrate` | POST | 현장 보정 | 송신기 위치들(폰 AR 좌표)과 측정 → 보정된 수신기 방향 |
| `/api/v1/result` | GET | 여러 자리를 합친 결과 | 위치, 방향과 그 방향의 기준 자리 번호, 의심 구역 모양, 합친 지도 퍼짐, 안내(멈춤 / 자리 더 재기), 시험실이면 의심 책상 3곳 |
| `/ws/v1/live` | 알림 | 진행 상황 · 경보 | 자세별 진행률, 새 카메라 의심 경보 |

`/api/v1/result`는 이전 초안의 `/api/v1/zone`을 대신한다. 한 자리 결과에서 방향을 바로 읽지 않고, 합친 위치를 가장 믿을 만한 자리에서 바라본 방향을 쓰기 때문이다([ai SPEC-002](https://github.com/DeteCam/ai/blob/main/specs/002-map-aware-direction/spec.md)).
