# 001 수신기 조종

## 배경

수신기(패널과 허브)는 노트북 없이 혼자 동작하고 화면이 없다. 사용자(숙소 이용자, 시험 감독관)는 폰 하나로 수신기의 모든 동작을 시키고 결과를 본다. 허브는 자기 Wi-Fi 로 HTTP 주소(API)를 연다 ([주소 계약](../../docs/주소%20계약.md)).

## 사용자 시나리오

1. **시험장** — 감독관이 패널 둘을 벽에 걸고 허브를 켠 뒤 앱을 연다. 패널마다 마커를 비춰 등록하고(002), 교실의 줄·칸을 넣는다. '찾기 시작'을 누르면 앱은 시험 내내 엿듣고, 카메라로 보이는 기기가 생기면 알린다. 그 기기를 고르면 자리 후보 세 곳이 확률과 함께 뜨고, 전송이 올 때마다 좁혀진다.
2. **몰카 찾기** — 방에 들어가 허브와 패널 하나를 켜고 '찾기 시작'을 누른다. 약 30초 뒤 의심 기기 목록이 점수와 까닭과 함께 뜬다. 애매하면 앱이 "방 안을 걸어 주세요"를 시킨다. 기기를 고르면 앱이 "패널을 창 쪽으로 돌려 주세요"처럼 다음 할 일을 한 줄로 알려 주고, 다섯 쪽을 다 재면 후보 세 곳이 뜬다.
3. **멈춤** — 어느 화면에서든 '멈춤'이 보이고, 누르면 1초 안에 재기가 멈춘다.

## 요구사항

| 번호 | 내용 |
|---|---|
| FR-1 | 허브 Wi-Fi 에 붙어 `GET /api/status` 로 상태를 1초마다 받는다 |
| FR-2 | 기기 표를 의심 점수 순으로 보여 주고, 점수의 까닭(새로 나타남, 올려 보내는 양, 보내는 무늬, 핫스팟)을 한 줄로 붙인다. '내 기기' 표시를 할 수 있다 |
| FR-3 | 걷기 확인의 '지금 할 일'(걷기·멈추기)을 큰 글씨와 진동으로 알린다 |
| FR-4 | 기기를 고르면(`/api/target`) 재기를 시작하고(`/api/locate`), 쌓은 전송 수와 후보 셋을 보여 준다 |
| FR-5 | 교실 설정: 줄·칸 수와 첫 자리·끝 자리로 자리표를 만들어 `/api/seats` 로 보낸다. 자주 쓰는 교실은 저장해 둔다 |
| FR-6 | '멈춤'은 모든 화면에 있고 `/api/stop` 을 보낸다 |
| FR-7 | 패널마다 연결, 배터리, 자리 등록 여부를 보여 준다 (`/api/health`) |
| NFR-1 | 한 손으로 쓸 수 있다: 주요 단추는 화면 아래 절반 |
| NFR-2 | 통신이 끊기면 3초 안에 알리고, 다시 붙으면 하던 화면으로 돌아온다 |
| NFR-3 | 결과에는 늘 '확정이 아님'이 드러난다: 자리 하나가 아니라 후보 세 곳과 확률 |

## 수용 기준

- 가짜 허브(`receiver/firmware/pi/node.py --dry`)로 시나리오 1·2 를 처음부터 끝까지 돌릴 수 있다.
- 멈춤을 누른 뒤 `status.state` 가 1초 안에 idle 이 된다 (10번 가운데 10번).
- 통신을 끊었다 이었을 때 앱이 죽지 않고 상태를 다시 맞춘다.

## 범위 밖

- iOS. 클라우드 계정·기록 동기화. 패널 장치 코드 올리기.
- 허브 없는 구성(패널 ↔ 폰 블루투스)은 패널이 실물에서 된 뒤 따로 스펙을 쓴다.
