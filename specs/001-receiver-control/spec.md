# 001 수신기 조종

## 배경

수신기는 노트북 없이 혼자 동작하고 화면이 없다. 사용자(숙소 이용자, 시험 감독관)는 폰 하나로 수신기의 모든 동작을 시키고 결과를 본다. 수신기는 자기 Wi-Fi 로 HTTP 주소(API)를 연다 ([receiver 스펙 005](https://github.com/DeteCam/receiver/tree/main/specs/005-standalone-control)).

## 사용자 시나리오

1. **몰카 찾기** — 방에 들어가 수신기를 켜고 앱을 연다. '찾기 시작'을 누르면 탐지(약 30초) → 의심 기기 목록 → (필요하면) 걷기 확인 → 위치 측정 순으로 앱이 다음 할 일을 한 줄씩 알려 준다.
2. **시험장** — 감독관이 좌석 배치와 수신기를 놓을 수 있는 곳을 고르고 '찾기 시작'을 누른다. 앱이 "다음은 ○○ 쪽으로 옮기세요"를 알려 주고, 끝나면 자리 후보 3개를 보여 준다.
3. **멈춤** — 어느 화면에서든 '멈춤'이 보이고, 누르면 1초 안에 모터가 선다.

## 요구사항

| 번호 | 내용 |
|---|---|
| FR-1 | 수신기 Wi-Fi 에 붙어 `GET /api/status` 로 상태(idle·busy·error)를 1초마다 받는다 |
| FR-2 | 탐지(`/api/detect`) 결과의 기기 표를 의심 점수 순으로 보여 준다. 점수의 근거(전송량, 올리는 비율, 처음부터 켜짐 등)를 한 줄로 붙인다 |
| FR-3 | 판별(`/api/identify`)의 '지금 할 일'(걷기·멈추기)을 큰 글씨와 진동으로 알린다 |
| FR-4 | 측정(`/api/measure`)을 시키고 진행률(스캔 몇 번째)을 보여 준다. 몰카 찾기는 `tilt3`/`tilt6`, 시험장은 수신기가 정한 계획을 쓴다 |
| FR-5 | 시험장 모드: 좌석 배치(줄·칸 수, 간격)와 놓을 수 있는 곳을 입력해 `/api/exam` 으로 보낸다. 자주 쓰는 교실은 저장해 둔다 |
| FR-6 | '멈춤'은 모든 화면에 있고 `/api/stop` 을 보낸다 |
| FR-7 | 수신기 상태(전압 경고, 온도, 관절 각)를 `/api/health` 로 보여 주고, 원점 잡기·판 0° 맞추기 같은 정비 동작은 '정비' 화면에 따로 둔다 |
| NFR-1 | 한 손으로 쓸 수 있다: 주요 단추는 화면 아래 절반 |
| NFR-2 | 통신이 끊기면 3초 안에 알리고, 다시 붙으면 하던 화면으로 돌아온다 |
| NFR-3 | 결과에는 늘 '확정이 아님'이 드러난다: 시험장에서는 자리 하나가 아니라 후보 3개와 확률 |

## 수용 기준

- 수신기 없이 `firmware/host` 의 가짜 수신기로 시나리오 1·2 를 처음부터 끝까지 돌릴 수 있다.
- 멈춤을 누른 뒤 `status.state` 가 1초 안에 idle 이 된다 (10번 가운데 10번).
- 통신을 끊었다 이었을 때 앱이 죽지 않고 상태를 다시 맞춘다.
